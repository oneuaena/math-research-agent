# Math Research Agent 1.3.0

## What changed

Version 1.3.0 adds the first Discovery Engine for **finite, explicitly encoded construction problems**. It is a computational-search capability, not a claim that an LLM can autonomously solve or formally certify arbitrary open problems.

Given a zero-based finite universe, a fixed subset size, forbidden pairs, and coverage groups, the engine:

1. creates a deterministic seeded candidate population;
2. evaluates candidates in a bounded 1–32 Node worker-thread pool;
3. minimizes forbidden-pair violations while maximizing coverage, spread, and archive novelty;
4. retains nondominated Pareto fronts in a bounded archive;
5. forms new candidates by deterministic parent selection, recombination, and mutation;
6. checkpoints the population, archive, exact PRNG state, and evaluation count after every completed generation.

The Construction Discovery UI displays the exact JSON input, seed/budget, latest checkpoint, and leading archive candidate. A pause terminates active evaluators and leaves a resumable record. On application restart, a previously running discovery run is converted to `PAUSED`; it is never silently called complete.

## Trust and safety boundaries

- The evaluator is fixed and data-only. It does not execute JavaScript, Python, prompt text, or an evaluator supplied by a model or renderer.
- Input validation limits the universe, candidate size, pair/group counts, worker count, and total work. A run cannot exceed 1,000,000 candidate evaluations.
- Discovery records are main-process-only; the renderer cannot create, overwrite, or delete them through the generic records API.
- A returned candidate is computational search output, not a theorem, counterexample certificate, semantic translation certificate, or `FORMALLY VERIFIED` result.
- The prior Formal Binding Gate remains intact: Lean kernel acceptance certifies the frozen Lean statement, while original-language equivalence retains its explicit confirmation boundary.

## Not included

This release does not claim to deliver an LLM-driven construction encoder, arbitrary evaluator execution, a distributed 32/64/128-machine cluster, an interactive Lean proof-state/tactic search engine, semantic-equivalence certification, or a cross-project theorem/lemma database. Those are separate research/product milestones.
